# 滞后特征方法说明

## 概述

系统现在支持两种滞后特征构造方法，可以通过配置文件中的 `lag_method` 参数进行选择。

## 配置参数

在配置文件的 `feature_engineering` 部分，添加了新的参数：

```yaml
feature_engineering:
  lag_length: 3  # 滞后窗口长度
  group_key: null  # 分组键，如果需要按组构造特征
  lag_method: 'direct'  # 滞后特征方法：'direct' 或 'statistical'
```

## 方法1: 直接拼接 (direct)

**配置值**: `lag_method: 'direct'`

这是传统的滞后特征构造方法，直接创建多个滞后版本的特征。

### 特征生成规则

如果 `lag_length=3`，对于每个特征 `feature`，会生成：
- `feature_lag1`: 1个时刻前的值
- `feature_lag2`: 2个时刻前的值
- `feature_lag3`: 3个时刻前的值

### 优点
- 特征数量较多，信息保留完整
- 适合模型自己学习时序模式

### 缺点
- 特征维度增长快（N个特征 × lag_length）
- 可能增加过拟合风险
- 特征间相关性高

### 使用场景
- 数据量充足
- 模型容量大
- 需要保留完整的历史信息

## 方法2: 统计量构造 (statistical)

**配置值**: `lag_method: 'statistical'`

这种方法将滞后信息压缩为统计量，提取关键特征而不是直接拼接。

### 特征生成规则

如果 `lag_length=3`，对于每个特征 `feature`，会生成以下5个统计量特征：

1. **`feature_lag1`**: 上一时刻的值
   - 最近的历史值，通常最重要
   
2. **`feature_diff1`**: 与上一时刻的差值
   - 计算公式: `当前值 - lag1`
   - 反映短期变化趋势
   
3. **`feature_rolling_mean`**: 滚动平均
   - 计算过去 `lag_length` 个时刻的平均值
   - 窗口大小: lag_length
   - 反映历史趋势
   
4. **`feature_rolling_std`**: 滚动标准差
   - 计算过去 `lag_length` 个时刻的标准差
   - 窗口大小: lag_length
   - 反映历史波动性
   
5. **`feature_diff3`**: 与lag_length个时刻前的差值（仅当lag_length > 1）
   - 计算公式: `当前值 - lag_N`（N=lag_length）
   - 反映长期变化趋势

### 优点
- 特征数量固定（每个原始特征 → 5个统计特征）
- 降低维度，减少过拟合风险
- 提取了关键的统计信息：趋势、波动、变化
- 特征具有更明确的物理意义

### 缺点
- 信息压缩可能损失部分细节
- 需要合理选择lag_length

### 使用场景
- 数据量有限
- 需要降低模型复杂度
- 关注趋势和波动性
- 特征维度需要控制

## 参数说明

### lag_length

滞后窗口的长度，影响特征生成：

- **direct方法**: 生成 lag_1 到 lag_N 共N个滞后特征
- **statistical方法**: 作为滚动窗口大小，用于计算rolling_mean和rolling_std

推荐值：
- 时序数据: 3-7
- 高频数据: 5-10
- 低频数据: 2-5

### group_key

如果数据包含多个组（如多个站点、多个产品），可以指定分组键，确保滞后特征在组内计算。

```yaml
feature_engineering:
  lag_length: 3
  group_key: 'station_id'  # 按站点分组
  lag_method: 'statistical'
```

## 使用示例

### 示例1: 使用直接拼接方法

```yaml
# config/config_ahead.yaml
feature_engineering:
  lag_length: 7
  group_key: null
  lag_method: 'direct'  # 直接拼接
```

运行：
```bash
python main.py --config config/config_ahead.yaml
```

### 示例2: 使用统计量方法

```yaml
# config/config_ahead_statistical_lag.yaml
feature_engineering:
  lag_length: 3
  group_key: null
  lag_method: 'statistical'  # 统计量构造
```

运行：
```bash
python main.py --config config/config_ahead_statistical_lag.yaml
```

## 效果对比

假设有3个原始特征：`price`, `volume`, `volatility`

### Direct方法 (lag_length=3)
生成特征：
```
price_lag1, price_lag2, price_lag3
volume_lag1, volume_lag2, volume_lag3
volatility_lag1, volatility_lag2, volatility_lag3
```
总计：3个原始特征 × 3个滞后 = **9个新特征**

### Statistical方法 (lag_length=3)
生成特征：
```
price_lag1, price_diff1, price_rolling_mean, price_rolling_std, price_diff3
volume_lag1, volume_diff1, volume_rolling_mean, volume_rolling_std, volume_diff3
volatility_lag1, volatility_diff1, volatility_rolling_mean, volatility_rolling_std, volatility_diff3
```
总计：3个原始特征 × 5个统计量 = **15个新特征**

注意：虽然statistical方法在这个例子中特征数量更多，但当lag_length更大时（如lag_length=10），direct方法会生成30个特征，而statistical方法仍然只生成15个特征。

## 最佳实践

1. **从statistical方法开始**: 先尝试统计量方法，它通常能提供更好的泛化性能

2. **根据数据量选择**: 
   - 数据量 < 10000: 推荐statistical
   - 数据量 > 10000: 可以尝试direct

3. **根据lag_length选择**:
   - lag_length ≤ 3: direct和statistical都可以
   - lag_length > 3: 推荐statistical

4. **对比实验**: 两种方法都试一下，比较效果

5. **特征重要性分析**: 训练后查看`feature_importance.csv`，了解哪些统计量或滞后特征最重要

## 注意事项

1. **NA值处理**: 无论使用哪种方法，滞后特征都会在前`lag_length`行产生NA值，这些行会自动被移除

2. **数据泄露**: 确保测试集的滞后特征只使用测试集自身的历史数据，不要使用训练集信息

3. **计算效率**: statistical方法由于需要计算rolling统计量，可能比direct方法稍慢，但差异通常不大

4. **兼容性**: 所有现有配置文件都已添加`lag_method: 'direct'`作为默认值，保持向后兼容

## 技术实现

代码实现位于 `src/feature_engineering.py` 的 `FeatureEngineer` 类：

- `build_lag_features()`: 主入口，根据lag_method调用相应方法
- `_build_direct_lag_features()`: 实现direct方法
- `_build_statistical_lag_features()`: 实现statistical方法

滚动统计量的计算使用pandas的rolling API，确保在group_key存在时正确分组计算。
