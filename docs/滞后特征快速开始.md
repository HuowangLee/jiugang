# 滞后特征快速开始指南

## 5分钟快速上手

### 1. 选择滞后特征方法

编辑配置文件的 `feature_engineering` 部分：

```yaml
feature_engineering:
  lag_length: 3              # 滞后窗口长度
  lag_method: 'statistical'  # 选择方法
```

### 2. 两种方法对比

#### Direct方法（原有）
```yaml
lag_method: 'direct'
```
- 生成: lag1, lag2, lag3, ... (N个特征)
- 适合: 数据充足，需要完整历史信息

#### Statistical方法（新增）
```yaml
lag_method: 'statistical'  
```
- 生成: lag1, diff1, rolling_mean, rolling_std, diff3 (5个统计特征)
- 适合: 数据有限，关注趋势和波动

### 3. 完整配置示例

```yaml
# config/my_config.yaml
feature_engineering:
  lag_length: 3
  group_key: null
  lag_method: 'statistical'  # 使用统计量方法
  reserved_columns:
    - 'info_date'
    - 'info_hour'
    - 'price_diff'
```

### 4. 运行训练

```bash
python main.py --config config/my_config.yaml
```

### 5. 查看生成的特征

训练完成后，查看特征重要性：
```bash
# 输出目录中的 feature_importance.csv
```

对于原始特征 `price`，会看到：
- **Direct方法**: `price_lag1`, `price_lag2`, `price_lag3`
- **Statistical方法**: `price_lag1`, `price_diff1`, `price_rolling_mean`, `price_rolling_std`, `price_diff3`

## 推荐配置

### 初学者推荐
```yaml
lag_length: 3
lag_method: 'statistical'  # 统计量方法更稳定
```

### 数据充足时
```yaml
lag_length: 7
lag_method: 'direct'  # 保留更多历史信息
```

### 高维特征时
```yaml
lag_length: 5
lag_method: 'statistical'  # 控制特征维度
```

## 常见问题

**Q: 应该选择哪个lag_length？**
- 时序数据: 3-7
- 高频数据: 5-10
- 低频数据: 2-5

**Q: 哪种方法更好？**
- 没有绝对的"更好"，建议两种都试一下
- 一般来说，statistical方法更稳定

**Q: 会影响现有模型吗？**
- 不会，默认使用direct方法，行为保持不变

**Q: 可以随时切换吗？**
- 可以，只需修改配置文件的`lag_method`参数
